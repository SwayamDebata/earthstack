# Changelog

Frontend (earthstack). Backend pipeline changes are recorded separately in the
API repository.

## ModelEarth Ops

The authenticated operations surface at `/ops`, built alongside Mission Control
(`/dashboard/*`) rather than replacing it. Mission Control stays as the demo and
investor surface; Ops is the product a district office would actually use.

- **Severity vocabulary** (`lib/ops/severity.ts`). Adopted IMD's four-stage
  warning system (Green / Yellow / Orange / Red) with its published action
  words. Every severity carries a word and a glyph as well as a colour, so it
  survives greyscale printing, a projector and colour blindness. Brand cyan is
  deliberately excluded: severity never shares a colour with identity.
- **Plain-language layer** (`lib/ops/language.ts`). Elapsed time, coverage
  lines, data-source names and reason text rendered in the words an officer
  would use. Machine identifiers (`openweather`, `imd_bhubaneswar_rfnormal`)
  and statistical jargon (`p95`) are translated rather than printed raw.
- **Alert inbox** (`/ops`). The queue is the landing screen, not the map. Seven
  day default window with the older backlog counted and stated rather than
  hidden. Untouched alerts sort first; time since the alert is the largest type
  on each row. Only Red and Orange alerts are allowed to shout.
- **Alert detail and Evidence Mode** (`/ops/alerts/[id]`). Rainfall figures with
  provenance, river level only when a gauge is live, and an explicit ceiling
  when inputs were missing. Degraded scores are never renormalised to look
  complete.
- **Accountability loop** (`lib/ops/workflow.ts`). Acknowledge, log an action,
  close with an outcome. Append-only record. Role gates mirror the server gates
  that will replace them; jurisdiction filtering is deliberately not done in
  React, because a client-side filter is not access control.
- **Flood briefing** (`/ops/briefing`). Built as a sheet of paper: carries its
  own date and issuing office, leads with the verdict, states what it could not
  see, and prints and screenshots legibly. Print stylesheet drops the app chrome
  and forces ink on white. Plain-text export for WhatsApp.
- **Record** (`/ops/record`). Closed alerts, outcomes and the full action log.
  Counts before percentages: `n` is always printed and no rate is shown below
  ten closings.
- **Map** (`/ops/map`). Orientation only. The city list renders from the same
  data and is fully usable if the map never loads. `ml_score` is present in the
  payload and is never read: the shown score is `rule_score`.

### Typography and map

- Ops opts out of Space Grotesk. The brand face carries the landing page and
  Mission Control, where personality is the point; Ops is small type, dense rows
  and numbers read by someone who is tired. Inter for text, IBM Plex Mono for
  figures (slashed zero, unambiguous 1/l/I), tabular numerals throughout, all
  scoped to `.ops-root` so nothing else changes.
- The map is edited rather than accepted. Water and waterways are pushed up
  until the Mahanadi and the Brahmani are the strongest thing on the page, which
  is the right emphasis for a flood tool; settlement, POI, road and airport
  labels are switched off. Markers are severity plates that keep colour, glyph
  and name, and colliding plates are decluttered in screen space. The camera
  fits the covered cities rather than a hardcoded centre.

### Fixes found while building

- `tailwind.config.js` did not scan `lib/`, so every Tailwind class defined as a
  string in `lib/ops/severity.ts` was dropped. Light mode looked correct only
  because those colours happened to be generated by other components; in dark
  mode every severity row painted its light background. Added `./lib/**` to the
  content globs.
- Evidence Mode read guessed `raw_data` field names. Corrected to the live
  payload (`historical_p95_rain`, `rainfall_past_24h`, `rainfall_forecast_24h`,
  `rainfall_forecast_48h`) and added the 48-hour forecast, which is the lead
  time the engine is actually scored on.
- The map's style pass set `line-color` on `waterway-label`, which is a symbol
  layer. Mapbox throws on that, the exception escaped the layer loop, and every
  layer after it kept its defaults: the settlement and POI labels were never
  hidden and the clutter stayed. Each layer is now edited inside its own
  try/catch, so one wrong property costs one layer rather than all of them.
- Markers raced the style load. The style effect and the marker effect ran in
  the same commit, so `once('load')` could miss the event and `isStyleLoaded()`
  read false; the markers never painted. Gated on an explicit ready flag.
- A first attempt at label decluttering nudged by latitude and made the overlap
  worse, pushing Cuttack down onto Bhubaneswar. Whether two labels collide is a
  question about pixels, so it is now answered in pixels.
- The Ops map initialised from a `useEffect` with empty deps while the component
  was still early-returning a loading state, so the container was never in the
  DOM and the map never appeared. Switched to a callback ref.

### Not built (deliberately)

No signup, billing, SSO or SCIM. No new regions. No merged flood and heat
surface. No public API, webhooks or mobile binary. Authentication, server-side
jurisdiction scoping and durable audit storage are backend work and are not
started: the work record currently lives in browser storage only, and every
screen that shows it says so.
